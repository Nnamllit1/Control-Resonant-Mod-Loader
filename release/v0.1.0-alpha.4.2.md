# CRML Alpha 4.2

This release adds reusable Wasm input and runtime APIs while preserving existing ABI 1 mods.

- Mods can declare up to 16 named input actions in `mod.ini`. Each mod receives its own held-state bits through `input_actions()`, independently of noclip or physics mode. Existing fixed-control imports remain available.
- `capabilities()` reports the services both declared by the mod and available in the current runtime. `release()` requests cleanup of that mod's native leases without unloading it. Existing fuel, memory, call budgets and automatic cleanup remain in force.
- The SDK includes capability constants and a C/WAT input-actions example. The standalone host reports unavailable game/input services without reading desktop keys.
- Engine observation and inspection modules now live in `runtime/diagnostics/` as normal C++ sources. Their build and startup gates are unchanged.

- Normal startup prepares gameplay services from mod manifests, allowing movement, player visibility and prop damping together. Shared controller/input hooks preserve per-service ownership and cleanup. A service that fails compatibility checks does not disable other available services.
- Wasm physics continues after its diagnostic recording reaches the size limit or ten minutes. Per-operation time limits, stale-handle checks and restoration still apply.
- `physics_select_near` accepts a mod-chosen search offset and radius. The damping example supplies its region, value and duration in guest source and reports rejected requests. The older fixed-region selection import remains compatible.
- New `player.read` and `camera.read` capabilities return copied player position and selected-camera pose/lens state. They do not enable flight or grant camera ownership. `physics_read` returns owner-scoped damping and speed samples for a selected prop.
- The SDK includes fixed-width snapshot layouts and a state-watch example whose position and camera-change logic runs in Wasm. The physics example checks sampled damping after an accepted request.
- Engine research now traces authored audio controls through resource lookup, backend playing IDs and deferred emitter cleanup. These static findings do not enable audio playback imports.
- Research also covers deferred entity spawning and native UI resource, page and model lifetimes. A separately enabled development extension adds a Mods tab to the game's own options menu; settings-page creation is not exposed to Wasm.
- Experimental `ui.read` and `ui.activate` imports expose recognized startup screens and a bounded Continue action. The SDK's separate startup-skip example chooses eligible notices, timing and retries in Wasm. Consent screens and initial configuration remain interactive. The runtime alone does not skip screens.
- Experimental `media.read` and `media.skip` expose the reviewed boot-video adapter with a named playback snapshot and queued skip. The startup-skip example selects the boot resource in Wasm. Native initialization and the original two-second playback gate remain enforced; this is not arbitrary cinematic control or an instant-start guarantee.
- Experimental `ui.presentation` provides temporary, owner-scoped hiding by an exact native UI ID or class name. The startup example selects the splash element and renews a short lease while the engine finishes initialization. Continue is dispatched once per screen visit; repeated polling no longer resubmits the event during the same visit. Preference loading, saving and consent remain controlled by the engine.
- Boot-video observation is throttled at each reviewed call site, avoiding repeated metadata copying in the engine's busy startup loop while retaining the original skip gate.
- UI presentation works with embedded renderers that lack the CSS priority getter. A failed presentation request no longer prevents an independent Continue action from being dispatched.

Movement remains noncolliding. Collision-preserving flight and camera writes are not provided. Lua source loading is not included in this release.

Players should download **`crml-runtime-v0.1.0-alpha.4.2-windows-x64.zip`** and install mods separately. Mod authors should download the **SDK**. New action bindings and imports require Alpha 4.2; existing ABI 1 packages continue to work.

Close the game before updating and keep installed mods and settings. Compatibility with other loaders is not guaranteed. See [installation](https://crml.nnamllit.de/installation/) and the [Wasm API](https://crml.nnamllit.de/api/).
